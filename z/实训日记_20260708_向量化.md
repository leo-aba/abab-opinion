# 实训日记

**日期**：2026年7月8日
**项目**：AI Opinion Analytics —— 视频评论分析平台
**今日工作**：评论数据向量化

---

## 一、环境搭建与项目启动

今天正式进入项目的开发阶段。首先需要将前后端服务跑起来。这个项目的架构是 Python FastAPI 作为后端，前端则是静态 HTML 页面，由后端直接托管，不需要单独启动前端服务。

在启动过程中遇到了一点小波折。系统全局环境的 Python 缺少必要的依赖包，安装时又遇到了 Windows 下 GBK 编码问题导致 requirements.txt 解析失败。排查后发现项目根目录下已经有一个 .venv 虚拟环境，里面安装了完整依赖，包括 PyTorch 2.12.1、sentence-transformers 5.6.0 等。使用虚拟环境的 Python 解释器后，后端成功启动在 localhost:8000。

## 二、理解项目数据流

在编写向量化脚本之前，先梳理了项目的数据流程。清洗后的评论以 JSON 格式存储在 test 目录下，每条评论包含 cid 和 text 两个字段。项目使用 Qwen3-Embedding-0.6B 作为嵌入模型，该模型已下载到本地的 backend/models/embedding/ 目录下，需要通过 sentence-transformers 库加载使用。

配置文件中定义了数据目录结构，向量化后的输出应保存在 data/vector/ 下。

## 三、编写向量化脚本

基于对数据格式和模型路径的了解，编写了 test/embed_comments.py 脚本。脚本的主要流程是：扫描 test 目录下所有带 _cleaned 后缀的 JSON 文件，提取其中的评论文本，加载本地 Qwen3-Embedding 模型进行编码，最后将向量保存为 numpy 的 npy 格式。

考虑到实际使用场景，脚本支持通过命令行参数调整批处理大小，并且在编码时自动对向量做 L2 归一化，方便后续计算余弦相似度。

## 四、运行与验证

运行脚本后发现模型加载耗时约 38 秒，551 条评论的向量化耗时约 230 秒——这是在 CPU 环境下的表现，如果使用 GPU 会快很多。输出向量维度为 1024 维，文件大小仅 2.2 MB。

对输出数据进行了全面验证：检查了 NaN 和 Inf 的数量，确认没有无效值；检查了 L2 范数，所有向量都接近 1.0，说明归一化正确；检查了数值分布范围在 -0.16 到 0.19 之间，分布正常。同时输出了几条样本评论及其对应向量的前几维数据，直观确认向量与文本正确对应。

## 五、版本控制

将向量化脚本提交并推送到了 Gitee 远程仓库的 xc 分支，提交信息为 "feat: 新增评论向量化与聚类脚本"。

## 六、小结

今天的核心成果是打通了评论文本到语义向量的转换 pipeline。551 条评论成功转化为 1024 维的稠密向量，为后续的聚类分析和相似度检索准备好了数据基础。整个过程从环境配置到脚本编写再到数据验证，走通了一个完整的数据处理闭环。
