# 实训日记

**日期**：2026年7月13日
**项目**：AI Opinion Analytics —— 视频评论分析平台
**今日工作**：设置页面简化、默认评论数优化与侧边栏修复

---

## 一、做减法——删除两个不再需要的设置选项

软件产品有一个常见的陷阱：功能越加越多，设置页面越来越长，用户面对密密麻麻的选项无所适从。定期审视已有功能、果断砍掉那些不常用或不成熟的功能，和开发新功能同样重要。

今天对设置页面做了一次"减法手术"，删除了两个选项。

**删除"自动生成AI总结"**：这个选项的初衷是让用户选择是否在分析完成后自动调用大模型生成总结。但实际使用中，AI总结已经成为了分析流程的标准环节——不做AI总结的分析价值大打折扣。一个"可关闭"的开关反而让用户困惑：关闭了会怎样？分析结果会缺什么？与其让用户纠结，不如直接把它作为默认行为，不在设置中暴露。

**删除"异常预警"**：这个功能计划在负面情绪突增时发送预警通知，但实际上一直没有完整实现后端逻辑。一个"空壳"开关放在设置页面上只会制造虚假的预期——用户打开开关以为有用，但其实什么都不会发生。在产品开发中，UI上暴露的功能必须是真正可用的，否则就是欺骗性设计。

代码改动涉及多个层面。前端方面，`settings.html` 中移除了两个 `setting-row` 的 HTML 块和他们对应的 JavaScript 事件处理函数（`onToggleAutoAiSummary()` 和 `onToggleAnomalyAlert()`）。后端方面，`schemas/settings.py` 中删除了 `auto_ai_summary` 和 `anomaly_alert` 两个字段，API 的读写逻辑同步清理。总共删除了约60行代码，设置页面一下子清爽了很多——现在分析偏好只保留"默认评论数"一个选项，通知偏好只保留"分析完成通知"和"追踪报告频率"两个选项。

## 二、默认评论数——更细粒度的选择

创建分析页面（`create-analysis.html`）上，用户需要选择要抓取的评论数量。之前的选项是 [500, 1000, 5000]，跨度较大。对于一些评论数较少的视频，500条可能都抓不到；对于只是想快速试用的用户，1000条又显得太多。

今天把默认评论数的选项调整为 [100, 200, 500, 全部]，增加了100和200两个小量级选项，用"全部"替代了5000（因为"全部"的语义更清晰——用户不需要知道具体数字，就是想抓所有评论）。这个调整同时应用在创建分析页面的初始显示和设置页面的默认值下拉框中。

创建分析页面的具体实现是：在页面加载时根据用户设置中保存的默认评论数，自动选中对应的单选按钮；如果用户没有设置过，默认选中500。这个逻辑让重复使用的用户不用每次都手动选择评论数，提升了操作效率。

## 三、修复侧边栏JS语法错误

在整理代码的过程中发现了一个隐藏的bug：侧边栏的 JavaScript 代码中有一段模板字符串的语法错误，在某些浏览器（尤其是旧版 Safari）上会导致侧边栏渲染失败。这个bug比较隐蔽——Chrome 对模板字符串的容错性较好所以没有报错，但在严格模式的 ESLint 检查下会被标记。

排查后发现是模板字符串中的嵌套引号没有正确转义。SVG 图标中使用了双引号包裹属性值，而这些 SVG 又被嵌入在 JavaScript 的模板字符串中，形成了"引号嵌套引号"的情况。修复方式是统一将 SVG 内联代码中的双引号改为单引号（HTML 属性支持单引号），消除了语法歧义。

虽然这是一个小修复，但它让我意识到跨浏览器兼容性测试的重要性——不能只在开发时用的 Chrome 上验证通过就认为没有问题。

## 四、小结

今天的核心工作是"做减法"：删除两个不需要的设置选项、简化默认值的选择逻辑、修复隐藏的语法问题。这些改动让设置页面更简洁、创建分析流程更顺畅。在产品迭代中，"删除"往往比"添加"更需要勇气——承认某个功能没有被用户需要、或者实现得不够好，并及时止损，是成熟的工程态度。

经过这一轮清理，系统的设置页面从最初拥挤的多个选项精简到了真正核心的几个配置项，用户在设置页面停留的时间更短，理解和操作的成本更低。
